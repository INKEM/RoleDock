# ADR-0003：接收时绑定

- 状态：已接受（P0）
- 关联：`docs/spec/objects-and-state-machines.md` §3

## 背景

协作请求从发起到执行存在时间差，期间目标角色可能发生交接（代次切换、知识更新）。若路由跟随"最新状态"，同一请求的行为会随时间漂移，无法审计；若固定在发起时刻，又可能与接收时已完成的交接脱节。

## 决策

在**接收事务**内固定请求的目标代次与知识快照（`binding`），以接收那一刻的最新继承者为准。已有请求（排队中、运行中）此后**不自动迁移**；新请求自然绑定新代次。原请求保留旧快照，保证执行与审计的可复现性。

## 后果

- 正面：路由行为确定且可审计；请求与交接并发时语义明确（以接收事务先后为准）。
- 负面：排队久的请求可能基于旧知识执行；需要结果消费方留意请求的绑定代次（结果元数据中可见）。
