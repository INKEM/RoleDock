# ADR-0001：单协调器

- 状态：已接受（P0）
- 关联：`docs/spec/identity-and-permissions.md` §4

## 背景

RoleDock 需要在原型阶段保证状态一致性（唯一主指针、接收时绑定、比较并交换），同时支持外部动作（宿主会话创建、执行）不在数据库事务内的现实。多协调器会引入分布式一致性成本，超出 v0.1 原型需要。

## 决策

每个工作空间由**单个协调器进程**写入。核心通过端口接口访问存储、会话执行与产出空间；数据库事务保证原子状态变更，外部动作通过**待投递记录（outbox）**衔接：事务内记录意图与创建键，动作完成后回填，重启后按创建键对账。

## 后果

- 正面：一致性语义可以用单数据库事务表达（CAS、唯一指针、接收绑定）；原型复杂度可控。
- 负面：单工作空间写入吞吐受限于单进程；协调器故障期间外部动作状态需对账恢复。
- 演进：多协调器/多节点一致性延后，需要时以独立提案引入，不改变现有对象语义。
