# ADR-0007：桌面管理 GUI 与外部会话显式锚定

- 日期：2026-10-13
- 状态：产品方向已接受；操作契约为待实施设计，未交付运行时能力
- 依据：用户要求以桌面 GUI 为主要入口，在会话中授权角色，由 Agent 执行显式锚定；补充选择“只保留外部 Harness 会话接入适配口”。
- 关联：[详细实施计划](../DESKTOP_GUI_PLAN.md)、[当前复验](../phase-reports/P0-P5-revalidation.md)

## 决策

RoleDock 提供桌面管理 GUI，管理角色包、工作空间、授权、外部会话绑定、角色主指针、知识和请求收件箱。聊天、模型运行、用户会话历史与工具执行由外部 Harness 承担。首版不开发内置聊天 Harness；CLI 保留为开发、诊断和兼容入口，用户主流程不依赖命令行。

用户在外部会话中表达授权，宿主的受信连接提供可验证的人类授权事件。Agent 调用显式 `sessions.anchor` 操作，核心核对授权、宿主会话身份、角色契约、策略与主指针基线后，准备知识、取得宿主载入确认，再事务激活绑定。自然语言角色自述或 Agent 自报 `role_id` 不能作为授权凭据。

一个外部会话在首版只能锚定一个角色实例。锚定时点之前的聊天不回溯获得角色身份，也不自动写入可分享知识。已有角色采用显式授权的继承方式；恢复已有绑定不增加代次。旧实例随新主指针激活立即失去正式发布权。

授权范围来自所有者决定和工作空间策略上限。Agent 只能消费已授权范围；角色包请求、模型输出、外部文档和工具返回不能签发授权。授权已经具体且可验证时，不增加重复确认步骤；只有角色歧义、权限超范围或继承意图缺失时才要求补充信息。

GUI 与 Agent 工具通过同一个持锁的协调器服务访问状态。GUI 渲染进程和每个 MCP 连接不能各自打开写库。所有者管理连接与会话连接使用不同权限面，数据库、测试夹具和任意回执写入不暴露给 Agent 工具。

## 后果

需要新增受信外部会话登记、授权事件、锚定状态与对账协议，并将 MCP 会话工具提前到 P5 后续子阶段。现有 `sessions.open` 创建新宿主会话的语义不能假称为锚定当前会话。

适配器必须分别声明人类授权事件、当前会话身份、角色材料载入确认、独立分支隔离和结果读取能力。不具备授权来源或当前会话接入能力的宿主，只能展示受限状态；仅安装通用 MCP 工具不能证明已经锚定。

真实 Harness 尚未确定。桌面容器、IPC 方式和外部宿主 SDK 的选择及精确版本留到实施时按官方接口验证，更新 `toolchain.md`；本 ADR 不引入任何依赖或修改现有协议 Schema。
