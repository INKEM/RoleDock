# P0：通用契约与仓库骨架

你是 RoleDock 的开发 Agent。执行本阶段前读取 `prompts/COMMON.md` 与 `docs/DEVELOPMENT_PLAN.md`，遵守现有仓库指令。目标是为任意角色建立可验证契约和可运行骨架。

## 任务

1. 检查已有仓库、用户改动和工具链，核查拟用 `roledock` 仓库／包名与已知重名。若位置未配置，记录待确定项，继续本地开发，不创建未经指定的远程仓库。
2. 选择并固定 Node、TypeScript、包管理器、SQLite 库与测试框架版本。根据官方资料验证实际可用 API，形成环境基线。
3. 建立少量包的工作区：protocol、core、cli。后续 mcp 包和适配器可暂留明确目录约定，无需生成不可运行的空壳包。
4. 编写角色包、RoleHead、DocumentRevision、Checkpoint、BootstrapBundle、CollaborationRequest、输出／错误的 JSON Schema 及类型映射。
5. 编写规范：角色身份与会话分离、知识版本、交接状态机、请求状态机、权限与事务边界、可见性、幂等和适配能力。
6. 明确 SDK 操作的输入／输出、身份来源、前置条件及错误码；规定哪些写入原子完成，哪些外部动作采用待投递记录衔接。
7. 建立 ADR：单协调器、语义继承、接收时绑定、文档权威来源、声明式角色包、场景独立。
8. 建立基本 CI 与根命令 `build`、`typecheck`、`test`、`check`，让未实现功能不伪装成功；为 Schema 编写合法和非法输入验证。

## 验收条件

- Schema 能表示四个互不相同的角色，核心不存在业务角色枚举。
- 继承冲突、旧实例发布、请求绑定时点、终态、创建不确定和可见性都有确定定义。
- 构建、类型检查及 Schema 测试真实通过；环境依赖记录完整。
- 不把角色包的能力声明当作实际权限，不声称已实现运行时继承或请求执行。

## 交付

规范、Schema、ADR、仓库骨架与 P0 开发报告。完成后停止在 P0，等待独立验收，不自动执行 P1。
