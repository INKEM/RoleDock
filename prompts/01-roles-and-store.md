# P1：自定义角色与持久状态

你是 RoleDock 的开发 Agent。读取 `prompts/COMMON.md`、开发计划、P0 规范及 P0 验收报告。确认 P0 已通过；若有未解决的前置问题，先明确并修复。

## 任务

1. 实现本地角色包加载、Schema 校验、版本与内容哈希记录。校验角色 ID 冲突、缺少模板、路径穿越、符号链接越界及不允许的远程 Schema 引用。
2. 实现 Workspace、RoleDefinition、RoleHead、AgentInstance、Session 及后续对象所需的 SQLite 表、迁移机制和事务存储接口。
3. 建立单协调器写入约束和工作空间隔离。多个协调器同时打开同一工作空间时，第二个明确失败，不能出现两个独立主状态。
4. 实现 roles.install/list/resolve；新角色允许无主实例，resolve 返回明确未初始化状态。
5. 建立受信会话身份与能力作用域模型。CLI／SDK不能仅凭自报 role_id 获得发布权；先定义本地所有者管理入口与会话调用入口。
6. 建立文档版本、knowledge_revision、幂等键和待投递事件的存储基础。外部执行此阶段不实现，但事务边界必须可测试。
7. 提供 demo-team 与 custom-role 角色包；custom-role 使用与示例不同的角色 ID 和职责。

## 验收条件

- 两个角色包可安装和查询，重启后状态仍在；冲突版本／角色 ID 返回结构化错误。
- 权限需求声明不自动变成会话能力。
- 跨工作空间读写、包路径越界和错误迁移被拒绝。
- 事务回滚不留下半安装角色包，状态存储不依赖某业务角色名称。
- 单协调器约束有真实进程或锁级验证，不能只写在 README。

## 交付

角色包加载器、状态层、权限身份基础、示例包、必要测试与 P1 开发报告。不得把尚未完成的会话／请求流程标为可用。
