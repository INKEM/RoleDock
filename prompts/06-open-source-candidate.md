# P6-R：桌面与外部锚定的独立开源候选版

你是 RoleDock 的开发 Agent。读取共同约束、开发计划、桌面计划、P5-H/P6-G 验收报告和所有未解决问题。前置是 P5 原总体条件已通过，且 P6-G0–G7 与 P6-G 总体均已独立验收 PASS；G-min 或单个页面通过不能替代。目标是形成独立可安装、可验证、可发布的 RoleDock 候选版。

## 任务

1. 复用 P5-A 已核查并固定版本的官方 MCP SDK 与会话连接，补齐工具／资源绑定文档和打包；不重建另一个独立写库的 stdio 协调器。身份绑定、文档可见性、写入权限和请求状态始终复用核心校验。
2. 定义 MCP 连接身份策略：明确用户管理入口与角色会话连接的区别。不能让模型通过任意 role_id 切换成其他角色或调用管理员能力。
3. 整理一致性套件：角色包、文档、知识版本、继承、独立请求、并发、幂等、恢复、可见性和导出。真实 Harness 验证与不依赖模型的 CI 分别报告。
4. 在干净检出和临时工作空间中运行安装、构建、测试、示例与打包。核查发布产物实际包含必要文件，排除运行数据库、凭据和私密日志。
5. 完成 README、快速开始、协议／API、角色包作者指南、适配器指南、已验证能力、已知限制、CHANGELOG、LICENSE、CONTRIBUTING 和安全报告渠道。
6. 写学术扩展接入说明，仅描述 roledock-academic 如何通过发布接口扩展；核心不导入领域对象或论文流程。
7. 生成 0.1.0-rc.1 本地候选包、发布说明和门槛报告。若发现前序真实宿主或 GUI 验收基线发生变化，停止稳定发布，保留本地候选并复验受影响条件。
8. 远程仓库组织、包名及发布位置只有在用户已明确给出并授权时使用；否则完成可审查发布材料，记录剩余远程动作，不能编造 GitHub 或包发布链接。
9. 对桌面安装包、共享协调器服务、MCP 与真实适配器进行干净安装验证。首个验证平台明确记录，未验证平台不列为支持；主要流程只依赖 GUI 与外部会话，CLI 作为诊断入口；依据桌面计划 GUI-01–GUI-14 验证，尤其原 ZCode 桌面会话、真实点击和无开发仓库安装。

## 验收条件

- GUI、外部会话工具／MCP、CLI、SDK 的等价操作得到相同核心权限检查，绑定不能绕过旧代次或可见性限制；会话工具无管理员入口。
- 用户在同一外部会话授权后，Agent 显式锚定，材料载入、代次、撤销和对账有真实宿主证据；GUI 不自建聊天 Harness。
- 开发计划中的 v0.1 条件逐条提供证据；跳过项不计通过。
- 无学术应用也能运行通用示例，核心依赖没有领域模块。
- 候选安装包可在干净环境安装并运行，公开材料不泄漏本地运行数据。
- Release 状态、已验证能力与真实远程发布情况准确。

## 交付

桌面安装包、共享服务／MCP／适配器候选包、测试套件、发布候选材料、扩展说明与 P6-R 开发报告。实现完成仍待独立验收，通过后再按已有授权发布稳定版。
