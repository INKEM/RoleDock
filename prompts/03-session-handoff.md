# P3：会话继承与唯一最新继承者

你是 RoleDock 的开发 Agent。读取共同约束、开发计划、继承规范，以及 P2 开发与验收报告。使用 Mock HarnessAdapter 先证明状态机制。

## 任务

1. 实现 HarnessAdapter 接口、能力结果和 Mock；接口区分会话、运行轮次、结果、关闭与可选取消／恢复／原生分支。
2. 实现 sessions.open：首个角色主会话初始化，后续主会话 inherit=latest 自动准备交接包。
3. 实现 prepare → provision → activate → retire。准备固定旧 generation 和 knowledge_revision；创建新宿主会话并验证 BootstrapBundle 载入；事务内比较后切换主指针。
4. 旧实例变成 superseded，其正式发布即刻被核心拒绝；原用户聊天记录保持不被新增交接指令污染。
5. 为知识在准备期间变化、两个继承者并发激活、适配器创建失败和协调器中途退出定义恢复流程。
6. 恢复已有会话只在适配器声明能力时执行，不能当作下一代；不支持原生恢复时用新会话进行语义继承并显式返回方式。
7. 原生 fork 不作为必需能力。跨角色使用完整私人历史的原生分支应拒绝，保留可分享交接包路径。
8. 固定角色包版本，显式升级才载入新契约；旧会话不静默换职责。

## 验收条件

- 首次创建和第二次创建具有正确代次、前任和知识引用。
- 并发激活仅一个成功，失败者拿到 HEAD_CONFLICT，旧实例无法再发布。
- 准备期间知识变化触发重新准备；宿主失败保留旧主指针。
- consultation 类型会话不成为主实例，resume 不增加 generation。
- 创建状态不明时不盲目重复生成会话，恢复说明与测试符合能力声明。
- Mock 测试覆盖上述条件，报告明确仍缺真实宿主验证。

## 交付

会话与交接服务、适配接口、Mock、状态测试、更新规范与 P3 开发报告。
