# 所有开发阶段的共同约束

你正在开发 RoleDock：一个独立开源的通用 Agent 角色协议与参考运行时。请读取仓库 `AGENTS.md`、`docs/DEVELOPMENT_PLAN.md`、相关规范和前序验收报告，再检查现有代码。

当前产品方向见 `docs/DESKTOP_GUI_PLAN.md` 和 ADR-0007/0009/0011/0012。最新 B5-4 独立验收已裁定 P5-H 和 P5 整体通过，G-min 已完成；完整桌面 GUI 按 P6-G0–G7 分阶段推进，详见 ADR-0013 提案。身份与授权必须以已实施的受信事件／会话契约为准，不沿用早期“未实现／BLOCKED”作为当前事实。新增 GUI 操作先固化契约，不假称已有 owner 详情、通用订阅或角色代理。

如果蓝图所述文件尚未生成，以当前阶段要求创建；若开发计划本身缺失且无法从用户提供材料恢复，明确指出缺少的输入，不能自行编造前序验收通过。

## 开发行为

1. 只执行当前阶段和必要修复，不提前实现后续学术功能。
2. 先复用现有实现，保持用户未提交改动，不重建已有仓库或覆盖工作。
3. RoleDock 核心不能硬编码任何业务角色名称、角色数量或学术对象。
4. 模型与宿主通过适配接口接入，角色包是数据和模板，不能自行授予执行或发布权限。
5. 所有正式发布经核心校验，角色身份来自受信会话绑定，不能信任请求里的自报身份。
6. 每角色唯一主指针；交接激活原子校验代次和 knowledge_revision；旧实例无正式发布权。
7. 新请求接收时绑定最新继承者及知识快照；已有请求不自动迁移，不注入用户主会话。
8. 分支只能提出候选更新；临时文件、消息、结果与权限作用域独立。
9. 不把 Mock、固定回答夹具或跳过的模型测试写成真实 Harness 验证。
10. 工具链与 SDK 版本根据环境及官方资料核查后固定，保留锁文件；不要依赖猜测的 API。
11. 所需外部信息缺失时完成不依赖它的工作，报告具体缺口，不能虚构凭据、仓库位置或发布结果。
12. 验证应覆盖状态和边界，不写仅逐字重复实现的测试。修复发现的问题后运行必要回归。

## 阶段交付报告

完成后写入 `docs/phase-reports/Pn-development.md`，其中 Pn 是当前阶段编号，例如 P2。报告应包含：

- 实际基线：提交标识或工作区 diff 摘要。
- 当前阶段交付与对应验收条件。
- 主要文件和公共接口变化。
- 实际运行的验证命令、结果及证据位置。
- 失败、跳过、未验证和外部阻塞项。
- 必要的规范／ADR更新和影响。
- 下一阶段可用输入及尚未满足的退出条件。

最后回复用户当前阶段做成了什么、如何验证、剩余事项。报告状态写“待独立验收”；正式通过状态由独立验收流程给出。
