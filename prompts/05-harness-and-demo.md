# P5：Harness 接入与端到端演示

你是 RoleDock 的开发 Agent。读取共同约束、开发计划、适配契约，以及 P4 开发与验收报告。目标是从 Mock 状态验证走向真实宿主行为。

## 任务

1. 实现 process-bridge 适配器：通过结构化 command 与 args 启动进程，定义会话创建、BootstrapBundle 确认、轮次执行、结果和取消消息。不要用拼接 shell 字符串承载用户材料。
2. 为桥接实现真实进程测试，包括断线、创建键查找、并发独立会话和资源回收。固定回答程序仅作为协议夹具。
3. 检查当前环境里已有且用户授权使用的真实 Harness／SDK。选择至少一个，核查其官方接口和版本，实现 harness-reference；必要时用 bridge wrapper 接入，不猜测命令参数。
4. 未配置真实宿主或凭据时完成可独立完成的适配接口、桥接、测试、CLI 和文档，明确提出所缺宿主名称、可用调用方式及授权输入，不宣称真实闭环通过。
5. 实现 CLI：工作空间初始化、角色安装／查询、打开主会话、文档读写／候选、请求管理、知识导入导出与诊断。具体命令稳定记录在帮助与快速开始中。
6. 完成 demo-team：创建 builder、发布知识、explainer 文档读取与咨询、并发请求、builder 继承、后续请求转向新代次、旧实例发布失败。
7. 演示跨适配器语义知识迁移，并新增完全不同的 custom-role，证明无需修改核心。
8. 文档说明宿主启动钩子／wrapper 怎样在首个工作轮次前指定角色并载入状态；把 MCP 工具接入和自动会话继承明确区分。

## 验收条件

- Mock 与真实进程桥接通过同一适用契约测试，失败能力返回明确降级状态。
- 至少一个已配置真实 Harness 完成角色载入、继承和独立请求；无条件时报告部分完成，不能进入“原型全部通过”。
- CLI JSON 返回可供另一个 Agent 解析，人工说明不混入机器输出。
- 演示可重跑、无需污染用户现有主会话；迁移只恢复已持久化语义知识。
- 真实执行日志保留适配器、宿主及模型版本和结果引用，去除敏感凭据。

## 交付

桥接与真实宿主适配器、CLI、演示、适配指南和 P5 开发报告。既有真实宿主调用权限不因开发框架而自动扩大。
